## 1. 方案确认时的代码边界

- `BehaviorAgent._physical_adjacent_lane` 排除地图上的对向车道；双侧按固定顺序检查，选择第一个获准候选，未比较两侧代价。
- `BehaviorAgent._update_maneuver` 只用连续静止的 vehicle 触发绕障，不处理静态道具、移动逆行车或行人的专门避让触发。
- `predict_intent_modes` 优先使用地图车道方向，并把速度在该方向上的投影截为非负值。同车道逆行车的多意图轨迹因此可能停在原地，虽然基础运动预测仍保留其运动趋势。
- `assess_maneuver` 的后车间隙使用速度模长之差，不能直接作为迎面来车的接近速度；整车已入目标车道后忽略后车的规则，也须增加实际行驶方向判断。
- 行人预测参与风险评估，但 `run_step` 的危险行人分支会提前返回制动控制，尚未联合比较减速与侧向避让。
- 现有预测器只采集车辆和行人；标注器已经保存部分环境静态框，但道具 actor 未进入动态框列表，环境框也未进入驾驶规划。

## 2. 共用决策流程

候选应同时包含沿原路线减速／停车、车道内小幅避让、向左临时绕行、向右临时绕行。每条几何路径需要配套速度计划，再检查整车随时间的占用区域。

筛选顺序：

1. 道路连接、边界、车道线／隔离设施、整车足迹、转向曲率和速度可执行性。
2. 静态物体、车辆及行人的时空碰撞风险；同时检查进入段、避让段和恢复原导航路线的路径。
3. 在安全候选中优先沿原路线或使用同向车道；对向借道须单独授权且满足完整返回条件。
4. 同一优先级内比较最小间距、风险上界、减速度、横向加速度、jerk、借道时间和恢复距离。先缩小到安全程度接近的候选集合，再考虑行为多样性。

固定先左后右改为两侧共同评估。原导航路线始终不变，临时路径在安全可执行的条件下尽早恢复原路线；不以直线距离最短覆盖安全和舒适性。

## 3. 车道与车流方向

区分地图车道方向和每辆车的实际运动方向。方向依据路点切向、观测速度及轨迹历史；低速车辆结合朝向，避免速度接近零时随机翻转方向。所有接近速度使用有符号的相对速度。

| 情形 | 建议规则 |
|---|---|
| 两侧同向且都安全 | 比较整条路径代价；安全程度接近时可概率选侧 |
| 一侧同向、一侧对向 | 同向候选可行时，始终优先同向，不随机选择对向 |
| 同向侧阻塞，对向侧看似空闲 | 仅在允许对向借道、边界允许跨越、有效可见范围充足，且整段通过和返回都可行时考虑 |
| 对向车在相邻车道稳定行驶 | 不因邻车存在就制动；判断其足迹／预测是否与本车路径相交 |
| 对向车出现在拟进入车道 | 用双方接近速度及完整占道时间判断，不能复用同向后车 TTC 差速公式 |
| 同车道逆行车辆 | 立即进入冲突预测和候选评估，不等待静止 2 秒；同时考虑对方未来继续逼近 |
| 两侧都不安全 | 提前减速／停车，不因另一侧地图标为 Driving 就强行进入 |

对向借道不能只检查未来固定 3 秒。检查时间至少覆盖进入、通过、返回及时间余量；所需观测距离随双方速度和占道时间扩大。视距不足、弯道／坡顶遮挡、返回空间不确定、隔离设施阻挡时不接受常规对向借道。地图真值中没有检测到来车，不能直接等同于有足够视距。

常规绕障和紧迫冲突避让分开处理：紧迫情况下比较可执行的避碰方案；没有安全侧向方案时保持稳定制动，不随机穿入未知区域。

## 4. 静态物体

建立内部共用障碍表示：来源、稳定标识、世界坐标定向包围盒、垂直范围、速度和预测。环境静态框按地图缓存并建立空间索引，动态生成的静态道具逐帧维护，避免每帧遍历全图。

需要覆盖道路上的护栏／路障、施工物、箱体、锥桶等实际碰撞物。过滤路面、标线等不可作为障碍的类别；通过高度、道路空间重叠和来源去重，避免桥梁上方物体、重复环境框、路边设施导致无故绕行。不能默认每个渲染 mesh 都有准确可用的碰撞框，需对支持的 CARLA 对象逐类验证。

静态物体不需要车辆“静止 2 秒”的判断；根据几何阻挡和足够规划距离触发。若车道内偏移已有足够间距，优先车道内避让，避免不必要地借用整条相邻车道。

供回放／训练读取的道具框沿用现有 bbox 数据结构和现有 static 语义，不改变现有字段含义或增加行为枚举。新接入对象须验证缓存确实解码并保留；若已有消费者只接受车辆／行人，应同步修正过滤逻辑并按真实不兼容性决定是否升级缓存版本。

## 5. 突发行人与移动冲突

行人应有停止、继续穿越、加速穿越／可能折返等带不确定性的候选运动趋势，并保留新出现目标尚无历史轨迹时的合理速度范围。首次观测不能假设静止，横向避让也不能仅绕过其当前坐标。

比较纯制动、减速并在车道内偏移、减速并向安全侧绕行三类方案，确认不会把行人挤进避让路径或制造新的车／人冲突。舒适性用于安全方案之间排序，不能减少必要的制动；制动与转向须联合满足车辆可执行能力。

用户补充确认：行人主动避让同样必须完整评估左右两侧的车辆、行人、静态障碍和返回路径。不能在行人紧迫分支中跳过旁侧安全检查。

紧迫危险不等待静止计时或常规 0.5 秒间隙确认。只有通过更严格即时可执行性和碰撞检查的候选才可执行；已发生物理上不可避免的冲突时，不声称一定能通过转向消除碰撞。

## 6. 概率选择与状态保存

不增加现有行为状态／决策原因类别。内部决策记忆记录检测、候选评估、执行承诺、等待／中止和恢复的阶段，映射回现有 YIELD／STOPPING／AVOID_LEFT／AVOID_RIGHT／RECOVER_LEFT／RECOVER_RIGHT 等状态；绕障仍不是导航指令，恢复仍为并行指令。

多样性只作用于安全过滤后的同等级候选：可在安全程度接近的左／右方案、允许范围内的避让幅度与动作时机之间选择。风险明显更高的候选不参与抽样，同向可行时对向候选不参与抽样。

建议随机键为固定配置种子、场景稳定键、原路线道路／车道标识、事件进入时的量化位置、冲突对象稳定锚点和事件计数。使用明确的稳定哈希，不依赖 Python 内置 hash、墙钟时间或可能随重载变化的 actor ID。只在事件进入或已承诺方案失效时抽样，不随每帧整数坐标变化重抽；设置承诺和退出迟滞，安全失效可立即打断。

原始 expert 诊断保存候选、拒绝依据、代价、最终选择、种子／哈希、抽样序号及执行记忆。若需要中途恢复，必须保存事件锚点、计时、抽样计数、锁定方案和恢复目标。复现承诺是“相同配置、观测序列和决策记忆得到相同输出”；CARLA 物理本身的逐位一致性须单独验证。

## 7. 分阶段交付与测试

先处理上轮 0.326m 的近障间距和行驶中紧急制动片段，再扩展以下能力。每阶段均单独生成标准 scene_*/lmdb、索引、关键帧和原始诊断，初测完成后等待人工查看，不同时推进下一阶段。

1. **方向修正与双侧选择**：修复逆行预测、相对速度和错误忽略后方目标；实现双侧候选比较、严格同向优先及有条件对向借道。
2. **静态物体**：道路内道具和环境碰撞物，含车道内偏移、跨线绕行和无路可绕停车；同步回放及缓存读取。
3. **移动冲突主动避让**：同车道逆行、迎面车偏入本车道、突然横穿／折返行人；统一速度与转向规划，保留稳定制动兜底。
4. **可复现多样性**：在前面验证的安全候选上加入概率选择，验证事件承诺、不同种子的行为覆盖，以及同输入／同记忆的严格重放一致性。

测试同时覆盖低流量和密集交通，左右镜像与不同相对速度；包含两侧同向、一同向一对向、仅对向可借、双侧阻塞、绕行后无法恢复、遮挡、路口／弯道限制、静态物体跨车道、行人从两侧出现及多个冲突对象。

通过条件除传感器无碰撞外，还包括逐帧定向包围盒间距、道路边界、全程返回原导航路线、没有频繁左右切换；统计真实控制和运动学的制动片段、峰值减速度／jerk／横向加速度，不以决策原因计数代替舒适性。构造“刹停不及但侧向确实可避”的场景与“无安全侧向空间”的对照场景，验证避让触发和拒绝路径。
